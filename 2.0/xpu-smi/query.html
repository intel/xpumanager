Query

Print a report of the main attributes of each GPU, as an indented Key : Value listing: identity, PCI link, clock throttle reasons, memory, utilization, ECC, temperatures, power and clocks, and the processes using the device. Use Discovery for static detail such as compute resources and firmware components, and --query-gpu or Dump for any single metric. The report can be restricted to chosen sections, written as JSON, repeated at an interval, or saved to a file.

Synopsis

xpu-smi query
xpu-smi query --display [sections] --device [deviceIds]
xpu-smi query --json
xpu-smi query --loop [seconds] --count [count]
xpu-smi query --file [filename]

Options

-h, --help

Print this help message and exit.

-j, --json

Print the report as JSON instead of text. See JSON Output.

--verbose

Print every row, including those a device does not report, which are otherwise left out of the text and the JSON. A value the driver or OS says the device does not support reads Not Supported.

-d <deviceIds>, --device <deviceIds>, --id <deviceIds>

Device IDs or PCI BDF addresses to report on. Multiple IDs can be separated by a comma. Use -1 to select all devices. Without this option every device is reported.

--display <sections>

Comma-separated list of sections to print, from the table below. Names are case-insensitive. Sections always print in the order of the full report, whatever order they are listed in. Without this option everything is printed.

--loop <seconds>

Print the report again every <seconds> seconds until interrupted with Ctrl+C. On a terminal the whole report is drawn once and then only the lines whose values changed are rewritten, so unchanged data stays on screen. A line wider than the window wraps onto the rows below it. This needs the whole report, wrapped lines included, to fit in the window. If it does not, the report is printed once and a notice explains why, and nothing more is printed until the window is made large enough, at which point live updates start. Making the window smaller again prints the report once more. Use --display to select fewer sections if you want live updates in a smaller window. When output goes to a file or a pipe, each report is appended in full.

--loop-ms <milliseconds>

Like --loop, with the interval in milliseconds. Takes precedence over --loop.

--count <count>

Number of reports to print. Without --loop or --loop-ms a --count above 1 repeats once a second. A count of 1 prints a single report.

-f <path>, --file <path>

Write the report to <path> instead of the terminal. An existing file is overwritten.

Sections

--display accepts the names below. A field that belongs to a section is printed wherever it sits in the report, so --display PCI prints the PCI address fields from the PCI part of the report, and memory utilization appears under both MEMORY and UTILIZATION. A section or heading with nothing to show is left out. Without --display every section is printed except SUPPORTED_CLOCKS, which must be named (or ALL given) because it lists every clock the frequency range can be set to.

Section

Report content

IDENTITY

Product name and brand, stepping, index, DRM minor number, serial number, UUID, GFX firmware version, board part number, device state, whether the device is a physical or an SR-IOV virtual function, the recovery action it needs, and the PCI address

MEMORY

Memory total, used and free, memory type, number of channels and bus width, and memory utilization

UTILIZATION

GPU, memory, compute, render, media and copy engine utilization

TEMPERATURE

GPU core and memory temperatures and their configured shutdown and slowdown temperatures

POWER

Power draw and the current power limit

CLOCK

Current graphics, memory and media clocks, the graphics clock the driver requested (Applications Clocks), and the maximum graphics and media clocks

PCI

PCI address fields, class code and IDs, the physical slot, link generation and width (maximum and current), and throughput

ECC

ECC mode and aggregate error counts, in total and by RAS category: memory, PCIe, SoC internal, compute, fabric and scale errors (xe), or cache and non-compute errors, resets, programming errors and driver errors (i915)

EU_ARRAY

Nothing in this report. Use --query-gpu eu.active,eu.stall,eu.idle for the EU array figures

FAN

The fan speed, on devices with fans

COMPUTE

Scheduler mode, and the number of tiles, slices, sub-slices per slice and EUs

PERFORMANCE

Whether each clock throttle reason is active, the time throttled, and the performance factors, where the driver reports them

SUPPORTED_CLOCKS

The GPU core clocks the minimum and maximum of config --frequencyrange can be set to, summarised as low-high step N when evenly spaced. The memory clock cannot be set, so it has no list. Printed only when named

PIDS

Processes using the device

ALL

Everything above, including SUPPORTED_CLOCKS

Fields

Every row the report can print. Row is the label path in the text report, with the path to the value in --json output (under each entry of gpus) below it. Details gives the --display section that selects the row, its unit, and its source: the --query-gpu field that reads the same value, or the Discovery property it comes from. A row reads N/A when the device, driver or platform cannot supply its value; Meaning says when that is expected.

Reading the Report

  • A value the device, driver or platform cannot supply prints as N/A. Where the value needs something the caller lacks, the text report says what, for example N/A (requires CAP_SYS_ADMIN): CAP_SYS_ADMIN for the PCIe link generation and width, the atomic capabilities and Resizable BAR, which come from PCI configuration space; CAP_PERFMON for engine utilization; read-write access to the device’s /dev/mei* node for the GFX firmware version. The ECC error counts also read N/A as a non-root user. The report prints no diagnostic for such a value; set XPU_SMI_LOG_LEVEL=DBG to see why one is missing.

  • Measured values (power draw, utilization, throughput, bandwidth) are averaged over a 200 ms window that the first report waits for. In a loop each later report averages over the time since the previous one.

  • Values with a unit are shown to two decimals. JSON keeps the full precision.

  • GPU IP Version is the graphics IP version the driver reports, in hex. It identifies the architecture: newer devices have higher values.

  • Offline Pages counts the device memory pages the driver has retired after errors, on drivers with page-offline support. Memory Repair says whether the device has had a repair performed, such as remapping faulty memory. It is left out where the driver does not track repairs.

  • PCI: Host Max is the link capability of the root port the device is under, the CPU end of the path; a switch in between can limit the link further. PCIe Errors are the device’s AER counters since it was enumerated, and Atomic Caps Inbound and Atomic Requests come from its PCI Express capability, which needs root. All of these are Linux only, and left out where the device or OS does not report them.

  • Fan Speed, the Performance Factors, Throttled Time, PCIe Replays Since Reset, ECC Mode > Pending, the default, minimum and maximum power limits and Memory Power Draw come from Level Zero calls that many drivers do not implement; CRI’s driver supplies none of them. They are printed where the driver supplies a value, and with --verbose otherwise.

  • GPU Power Readings: Average Power Draw is the card’s draw over the window, Instantaneous Power Draw the driver’s reading at one moment, and GPU Domain Power Draw the GPU domain’s share. Current Power Limit is the sustained limit, or the burst or peak limit on a device without one; the burst and peak limits are listed on devices that report them.

  • BAR Memory is the device’s largest memory BAR, through which the host reaches device memory. Resizable BAR says whether it was resized; the driver reads that from PCI configuration space.

  • FB Memory Usage: Reserved is memory the driver keeps back (installed size minus Total). Used counts it, so Total is Used plus Free. A memory clock the driver reports as 0 reads N/A.

  • Utilization comes from the Sysman engine counters, or from the per-process engine times in fdinfo where those are unavailable; never from the EU array, whose metric stream is slow to open. Video and Video Enhancement split Media into its decode/encode engines (which Linux reports as one) and its enhancement engines, on devices that have them.

  • GPU utilization is the busiest engine’s share of the window. An engine counts as busy for all the time it has work scheduled, so it can read higher than eu.active under the same workload.

  • Applications Clocks shows the graphics clock the driver last requested, which the GPU runs at unless a throttle reason holds it back. Minor Number is the number of the device’s DRM card node, and reads N/A on Windows. Slot Number is the physical PCI slot the platform firmware names, and reads N/A on systems whose firmware names none.

  • GPU Recovery Action says what the driver reports the device needs: None, Reset (for example a wedged device), or Reset to repair.

  • As root, the GFX firmware version is read from the GSC firmware interface, which takes about 200 ms per device on some platforms. Devices are read in parallel, and the read overlaps the measurement window. On a device with an AMC the serial number and the board part number are read from the AMC, one after the other.

  • The slowdown and shutdown temperatures are the configured thresholds the Health command compares against, not sensor readings. Without a threshold configured for the device, the default shutdown temperature is lowered to the driver’s maximum for that sensor, as on CRI (125 C). The max operating temperatures are what the driver reports for each sensor, on devices that report one.

  • On Windows the kernel-mode driver version reads N/A.

  • Rows only some devices or drivers supply, such as the RAS categories under ECC Errors, are left out on a device without them, so it does not fill with N/A; the JSON output leaves out the same rows. --verbose prints them all, and Not Supported for a value the driver or OS says the device does not support; a value missing for another or an unknown reason stays N/A.

A device in survivability mode is listed with only its state and the recovery action (Firmware update and GPU reset).

JSON Output

--json prints one object. Its keys are the lower-case, underscore-separated form of the labels in the text report, and it has the same rows: a row the text leaves out is not a key, and --verbose adds them to both. A value that is not available, printed N/A in the text, is null. Numbers are strings in the unit shown in the text report, and processes is an array.

{
    "timestamp": "2026-10-21T13:28:16Z",
    "umd_version": "1.17.39980",
    "kmd_version": null,
    "level_zero_version": "1.33.1",
    "attached_gpus": 1,
    "gpus": [

            "pci_bus_id": "0000:03:00.0",

Examples

Report on every device:

xpu-smi query

Report only memory and ECC for device 0:

xpu-smi query --device 0 --display MEMORY,ECC

Save a report to a file:

xpu-smi query --file report.txt

Print the power and temperature sections every 5 seconds, 12 times, as JSON:

xpu-smi query --display POWER,TEMPERATURE --json --loop 5 --count 12
